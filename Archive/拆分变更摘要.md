# 模块系统按功能拆分 — 变更摘要

日期：2026-10-01
范围：module_scripts.py（阶段二完成）→ module_dialogs / module_game_menus / module_mission_templates / module_presentations / module_simple_triggers（本次推广完成）
验收：全链 29 个 process 编译通过；拆前拆后导出 txt 条数完全一致。

---

## 1. 背景与目标

原代码库将全部逻辑堆在单一大文件（如 module_scripts.py 数千行、module_dialogs.py 单文件 1MB+），多人并行修改同一文件时冲突密集。目标：按**功能职责**把每个 module 文件拆成「门面主文件 + 功能子文件」，实现一人一个子文件、互不干扰。

## 2. 拆分方案（门面模式 + 功能桶）

**门面（facade）主文件**只保留：
- 头部（import、常量、触发器名单等公共定义）
- `##split modules begin/end` 导入块（按序 from 子文件 import 各列表）
- 聚合行 `xxx = xxx_a + xxx_b + ...`（保序拼接）
- modmerger 块（原样保留）

**功能子文件**：`module_<类型>_<feature>.py`，各定义 `<类型>_<feature>` 列表，自包含完整 import 头。

**分桶依据**：
- scripts / game_menus / presentations / mission_templates：按**名字/功能前缀**分桶（按名引用，顺序无关）
- dialogs：按 **start_state** 分桶（引擎匹配键 = (partner, start_state)，首个匹配胜出 → 同状态同桶保序、跨状态互不竞争，行为安全）
- simple_triggers：按**内容样本关键词**分桶（按 tick 顺序执行，功能分桶会重排，风险低已接受）

## 5. 过程中修复的关键问题

1. **simple_triggers 分桶匹配失效**：匹配键误用条目首词（取到间隔秒数如 "24"），绝大多数条目落入 core_daily 桶 → 改用整段样本文本匹配，分桶恢复正常（7 桶均有条目）
2. **括号栈解析器尾部误判**：列表 `]` 前的注释块/空白段被当作条目，导致 core_misc 子文件出现孤立逗号（语法错误）与计数 +1 → 切分时跳过"纯注释/空白"尾段
3. **Python 2 编码**：含 UTF-8 中文的 bytes 调用 `.encode()` 触发隐式 ASCII 解码崩溃 → 直接写字节、去掉 `.encode()`

## 6. 后续注意事项

- 新条目追加到对应功能子文件末尾，**不重排已有条目**（列表顺序即 ID 编号顺序的硬约束仅对 items/troops 等持久对象生效）
- 子文件只 import 基础层（constants/ID/header），绝不反向依赖，防循环 import
- 公共名字（`dialogs` 等聚合变量）只出现在门面文件；子文件列表名带 `_feature` 后缀
- 功能 ↔ 文件索引见 `功能地图.md` §6.1
- 菜单聚合已从简单拼接改为 `_MENU_INDEX + _MENU_ORDER` 交错聚合（2026-10-02 修复"报告"跳转事故），新增菜单两步规范见 `功能地图.md` §6.1「菜单聚合机制」与 skill `menu-operations-guide`
